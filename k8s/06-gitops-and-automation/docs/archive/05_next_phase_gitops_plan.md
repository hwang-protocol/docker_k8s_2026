# 第 4 步：下一阶段 GitOps 规划

## 本步目标

这一页不要求马上落地，而是告诉学员：

- 为什么第一阶段之后必须继续进入交付阶段
- 接下来会怎样一步步进入 Docker、Git、Helm、Argo CD

## 当前承接点

到这里为止，我们已经有了一个可运行、可讲解、可继续扩展的样板应用。

下一步不再停留在“手工本地运行”，而是要把它推进成一个可构建、可交付、可被 GitOps 接管的正式工程。

## 下一阶段实施顺序

### 第 1 步：Docker 化

把前端和 3 个后端服务补齐 Dockerfile，并形成统一的本地构建方式。

### 第 2 步：镜像推送 Harbor

镜像统一推到：

- `harbor.qytk8s.com`

### 第 3 步：准备 Git 服务

在 `git.qytk8s.com` 上准备：

- `qytang-netdevops.git`

### 第 4 步：补齐 Helm Chart

把当前服务整理成 Chart，并把配置参数化。

### 第 5 步：安装 Argo CD

让 Argo CD 以 Git 为事实源，把应用同步进 Kubernetes。

### 第 6 步：演示更新与回滚

后续可以演示：

- 修改镜像 tag
- 修改副本数
- 修改页面文案
- 修改流量配置
- 通过 Git 提交触发更新
- 通过 Git 回退触发回滚

## 为什么这个顺序合理

因为它和学员的认知顺序一致：

1. 先理解应用
2. 再理解镜像
3. 再理解仓库
4. 再理解声明式配置
5. 最后理解 GitOps 控制器

## 后续你上课时可以这样过渡

可以直接说：

> 我们现在已经有了一个可运行的样板系统，下一步不再手工跑它，而是把它变成一个可以被 Git 管理、被 Argo CD 自动同步的正式上线工程。
