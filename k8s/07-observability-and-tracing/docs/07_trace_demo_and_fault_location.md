# 第 6 步：Trace 演示与故障定位

## 本步目标

用一条真实业务请求，把第七章的主线讲完整：

- 先从 K8s / 应用指标发现异常
- 再进入 Trace 找到慢点
- 最后定位到具体服务或下游调用

## 建议演示顺序

1. 打开 `Grafana`
2. 先看 `QYT NetDevOps` 总览大盘
3. 再看 Kubernetes 基础监控大盘
4. 触发一次业务访问
5. 打开 `Jaeger`
6. 在 `Jaeger` 中检索请求链路并查看瀑布图

## 推荐观察点

### 指标侧

- 某个服务请求量突然增加
- 某个接口延迟升高
- 某个 Pod 重启次数增加
- 某个节点资源吃紧

### Trace 侧

- `device-service` 是否最慢
- 下游调用是 `resource-service` 慢还是 `audit-service` 慢
- 数据库访问 span 是否异常
- 某个 span 是否把总耗时拉长

## 课堂结论

这一节要让学员真正建立下面认知：

- 看 Pod `Running` 远远不够
- Metrics 负责快速发现异常
- Trace 负责精确定位异常链路
- `Jaeger` 的瀑布图最适合课堂上讲解调用耗时分布
- K8s 指标和微服务 Trace 组合起来，才是完整的现代可观测闭环
